# Prepare a device-supported offline speech pack from the catalog

In **Offline startcheck → Bekijk offline spreektaalpakketten**, use **Controleer alle talen** to ask the Android **on-device-only** recognizer which of the 13 candidate language/region packs are installed, downloadable, online-only, unsupported or unknown.

For a locale that Android explicitly reports as **downloadable**, tap **Vraag lokaal spraakpakket via wifi aan…**. Tuddy displays the exact language code and asks for a separate confirmation. Only then does it call Android's `SpeechRecognizer.createOnDeviceSpeechRecognizer(...).triggerModelDownload` through the existing `OnDeviceSpeechPackController`. Active Wi-Fi is required; mobile data or an unsupported API refuses the request. Requests are **never** made for online-only or unknown languages, never made in bulk, and do not start speech capture.

While a request or targeted recheck is active, other scans and downloads are unavailable. The selected row displays Android-reported progress on Android 14+, pending/requested states, errors, and—only after a separate Android installed-support result—an installed state. Android 13 cannot confirm download progress and remains **requested** pending a fresh check. **Stop controle of voortgang volgen** releases Tuddy's transient observer and invalidates delayed callbacks; Android may still finish a system-owned queued download, so the stop button is not represented as a forced cancellation. **Controleer pakket opnieuw** checks just one candidate on-device with an eight-second service-response timeout. Closing the catalog or backgrounding the Activity drops all local follow state, callbacks and recognizers.

**Limitations:** The browser is device-provided ASR pack management for Android-supported spoken locales only, not a universal speech model store. Neither an Android catalog result nor a finished download proves real-world microphone quality, airplane-mode behavior or a complete Kurdish Kurmanji / Sorani / Pashto offline ASR + MT pair. P1 [issue #1](https://github.com/Zennay/Tuddy/issues/1) device acceptance and [issue #2](https://github.com/Zennay/Tuddy/issues/2) model/license/native-speaker gates remain open. No cloud speech fallback, model weights, hidden downloads, new permissions or VPS deployment.
