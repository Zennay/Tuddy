# Recently requested Android offline speech packs

Android may schedule an on-device speech model download and finish after Tuddy is backgrounded. The catalog does **not** automatically resume recording or download anything when reopened. Instead, Tuddy now retains a bounded list of **manual request attempts**, so users can find the original language again and choose to recheck it.

The saved record contains only the exact Android locale tag the user deliberately requested and a local timestamp; at most 24 tags may be recorded and only members of Tuddy's built-in 13 spoken candidates are accepted. App-private SharedPreferences are protected by the existing `allowBackup=false`; no transcript, spoken phrase, audio, installed-model receipt, device ID, API key, network endpoint or analytics is persisted.

After Android passes the Wi-Fi gate and the on-device controller enters an actual request attempt, Tuddy saves that locale. **The list never claims an installed pack**: the user sees “Eerder expliciet via wifi aangevraagd. Installatie is hiermee NIET bevestigd.” A separate **Controleer eerdere aanvraag opnieuw** button requests a read-only local installed-pack check, respecting the same timeout, lifecycle and no-cloud restrictions as the speech catalog. An individual **Vergeet deze aanvraagpoging** button deletes only this record (not an Android system model or language settings). Closing the dialog discards transient receipts, but does not discard explicitly requested locale history. There is no silent resumption of a system download or background checking.

Android 12 may not report installed speech languages; Android 13 may only report that a request was queued. Only a subsequently returned exact installed on-device language may be shown as ready. This does not address the full rights-cleared Kurmanji/Sorani/Pashto ASR+MT requirements of [issue #2](https://github.com/Zennay/Tuddy/issues/2), nor physical-airplane-mode acceptance in [issue #1](https://github.com/Zennay/Tuddy/issues/1).
